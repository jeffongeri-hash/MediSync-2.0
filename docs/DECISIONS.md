# Decisions (one line each)

- DB: plain Postgres 16 + Prisma 7 (pg driver adapter) locally and in CI; move to Supabase by changing DATABASE_URL.
- Raw sources stored as `text`, not `jsonb`, so they stay byte-identical; sha256 over original bytes is unique, which makes ingest idempotent.
- `patients` is a patient index; the canonical Patient resource is the source of truth for demographics.
- `audit_log` is append-only (DB trigger blocks UPDATE/DELETE), has no FKs, and `details` holds flat scalars only (no PHI).
- Synthea fixtures (seed 3, 3 years history, FHIR R4 + C-CDA) are committed so CI needs no Java.
- Pinned TypeScript 5.9 and ESLint 9 (not 7 / 10) for Next 16 tooling compatibility.
- `/demo` is server-rendered with no client JS, so `pnpm demo:snapshot` yields a faithful static copy; fonts load from a Google Fonts link (not next/font) for the same reason.
- Every `/demo` view writes one READ audit entry per patient shown.
- E2E (Playwright) runs in CI against `next start`; locally against `next dev`.
- Phase 1 canonical scope: Patient, Condition, MedicationRequest/Statement, AllergyIntolerance, Observation, Immunization, Procedure, Encounter, DocumentReference. Other types stay raw and are reported (INFO `unsupported_resource`).
- Canonical Zod schemas are loose (unknown fields kept) but enforce R4 required fields, status codes, primitive formats and choice[x] cardinality; an invalid resource is an ERROR with no canonical row (raw kept).
- INFO issues are aggregated per source (code + type + message, `details.count`); WARNING and ERROR stay one row per item for the review queue.
- C-CDA to FHIR is a hand-written TS mapper (fast-xml-parser) dispatched on entry templateId; unknown templates are WARNING `unmapped_section`, never dropped silently.
- C-CDA entry ids: the id root when it is a valid FHIR id (Synthea reuses FHIR UUIDs, so formats line up), else `ccda-<sha256>`; deterministic either way.
- C-CDA timestamps without an offset are taken as UTC (INFO `timezone_assumed_utc`); C-CDA Encounter.class is set to v3-NullFlavor UNK (INFO `defaulted_field`).
- NDJSON fixtures are generated from the committed bundles (`pnpm ndjson`): canonical types only, like `$export?_type=`, references rewritten to `Type/id`.
- Patient index rows come from the canonical Patient of any format, keyed by (source_system, Patient.id); multi-patient NDJSON sources have no patient_id and rows are attributed via subject/patient.
- A source is parsed once (`parsed_at`, `parser_version`); a resource not attributable to a known patient is WARNING `unknown_patient` and not stored.
- Same Type/id twice in one source: first kept; identical copies INFO, differing copies WARNING `duplicate_in_source`.
- Audit entries use a strict schema, so a misspelled field fails loudly instead of being dropped.
- Phase 2: `canonical_resources.resource` stays the copy as received; `mapped` is recomputed from it by a pure mapper whenever `MAPPING_VERSION` changes, so mapping never drifts.
- Terminology is local only (NLM hosts blocked), behind a `TerminologySource` interface; code tables hold the fixtures' codes, and SNOMED CT/LOINC check digits are verified offline.
- SNOMED CT to ICD-10-CM crosswalk is hand-written and unverified; derived codings carry `urn:medisync:extension:derived-coding`. `null` = no diagnosis code applies (INFO); missing = WARNING.
- Dedupe is per patient across formats and links (`duplicate_of_id`), never merges. Ids match only within one source system; fallback is code + clinical day with one row per source. Primary: Bundle > NDJSON > C-CDA.
- Provenance: `meta.source` = `urn:medisync:source:<system>#<source_record_id>` plus `source_system`/`source_date` columns; FHIR Provenance resources are generated at export (Phase 3).
- Units: a small UCUM table plus aliases sets `system`/`code`; values are never rescaled in Phase 2.
- Medication is a canonical type, attributed to the patient via the MedicationRequest/Statement that references it; NDJSON seeds `Medication.ndjson` last.
- `mapping_issues.stage` (INGEST/MAPPING/DEDUPE): a re-run replaces only its own stage's OPEN issues; RESOLVED/IGNORED ones are kept and not raised again.
- A `PARSER_VERSION` bump does not re-parse sources already ingested (sha256 idempotency); after a parser change, seed a fresh database.
- Phase 3 export source: primary rows only (`duplicate_of_id` null), from `mapped`; linked duplicates are cited in Provenance and never merged in; elements only a duplicate has are listed in the fidelity report.
- Export target: US Core 6.1.0 as an R4 `transaction` Bundle of POST entries without ids; fullUrls are `urn:uuid` derived from sha256 of `Type/id` (UUID v8 layout), so the same rows and export time give the same bytes.
- US Core conformance is checked locally (rules from memory): a missing mandatory element is ERROR `profile_violation` and the resource is not exported; absent must-support elements are one WARNING per resource; uncertain cardinality is treated as must-support. A Patient that fails blocks the bundle.
- A reference to a type outside the canonical model (Practitioner, Location, Organization) or to a resource not exported keeps only its display; an empty one gets "<Type> record not included in this transfer". It counts as lost.
- Codings derived from the unverified SNOMED CT to ICD-10-CM crosswalk are withheld from every export.
- Each exported resource gets one Provenance resource: author is the source system, transmitter is MediSync, and entities are the source documents by sha256, duplicates included. `meta` is replaced by the versioned profile.
- Completeness = (kept + changed) / leaf elements of the source `resource` as received, per type and overall. Changed means the same path with a new value; lost means no counterpart. id, meta and resourceType are not scored; additions are reported but not scored.
- `transfer_jobs` run synchronously from `pnpm transfer` and `POST /api/transfer` (dry run by default there). Each job writes one EXPORT audit entry, and its EXPORT-stage issues on dry runs too. Only a real export stores the bundle text.
- The transfer API returns job status and report, never the bundle. Since Phase 6 it needs a launched session for the patient (or demo mode) and the provider role.
- Phase 4 current chart = Bundle primaries as of a cutoff (latest encounter minus 12 months); conditions that abated after it show active. Incoming = the C-CDA rows. NDJSON copies are not reconciled.
- Phase 4 scope: Condition (problems if active on either side, else past history), MedicationRequest/Statement, AllergyIntolerance. Procedures are not reconciled yet.
- Pairing: dedupe link first, then same family + code + clinical day; the rest is NEW or CURRENT_ONLY. Rule flags are authoritative and always cite canonical ids; AI flags are separate suggestions.
- Drug classes, allergen terms and the ingredient table are local and unverified (src/reconcile/drugs.ts), keyed by the fixtures' RxNorm codes; class labels name the route for steroids.
- Reconcile writes only reconciliation_runs/items/claims/decisions and audit_log. Decisions are append-only (trigger); the latest per target wins; EDIT stores a provider-authored copy validated by the canonical Zod schema.
- Model input uses short aliases (C1.., I1..), never canonical ids; a citation is valid only if the alias was sent. Invalid claims are stored with reasons and never shown as suggestions.
- "No hallucinated conditions" is checked lexically: SNOMED disorder/finding/situation displays plus a synonym lexicon; a named condition must be on a cited row (else miscited) or on some row (else hallucinated).
- Model call: claude-sonnet-5-5 (ANTHROPIC_MODEL overrides), structured output (`output_config.format`, not forced tool_choice, which Sonnet 5.5 rejects), effort high, server-side refusal fallback `fallbacks: "default"`.
- Without ANTHROPIC_API_KEY the app uses a rule-built template summary, labelled as such. Sending records to the model writes an EXPORT audit entry (source anthropic).
- Evals are a frozen set in fixtures/eval (10 patients, 20 cases, 25 injected changes). CI replays recordings keyed by prompt version + input sha256; missing or stale ones are "not evaluated", never passed.
- The live call is streamed (`finalMessage`) with max_tokens 32000, since adaptive thinking counts toward the cap. A 400 keeps the API's message (truncated) in aiError; other failures keep only an error class.
- CI's eval step is report-only: replay never fails the build. `pnpm eval --strict` exits 1 when an evaluated case fails, for local gating.
- The app and the Phase 4 gate need no API key. The gate is the key-free eval (`pnpm eval --template --strict`, enforced in CI plus src/ai/eval.test.ts); the Claude summary and its pass rate are an optional enhancement.
- Phase 5 SMART: fhirclient 3 runs authorize/ready through our RouteAdapter (it ships no App Router adapter); the adapter's URL holds only validated values, so clientId, fhirServiceUrl or patientId never come from the query string.
- Launch: EHR + standalone, public client, PKCE S256 required; scopes `launch` or `launch/patient` + `openid fhirUser` + `patient/<Type>.read` for the 6 read types (SMART v1 style; SMART_SCOPE replaces the read scopes); no offline_access.
- Servers: one app registration per EHR, so client id (and optional scopes) is per server: `SMART_SERVERS=epic,oracle` + SMART_<NAME>_ISS/_CLIENT_ID/_SCOPE, or the single form SMART_ISS + SMART_CLIENT_ID. Redirect URI and SESSION_SECRET are shared.
- An EHR launch is routed by its exact iss; standalone by `?server=<name>` (default: the first server). Any other iss is refused, and so is a server without an authorization endpoint.
- smart_sessions row keyed by sha256 of an httpOnly SameSite=Lax cookie (8 h); fhirclient state sealed with AES-256-GCM (SESSION_SECRET, session id as AAD); tokens are discarded after the launch read.
- (Phase 5, superseded in Phase 6) id_token claims were read without a signature check.
- Launch read: Patient + Condition (3 US Core categories) + MedicationRequest + AllergyIntolerance + Encounter, next links followed only on the iss, missing Medications read by id; a failed search is reported, a failed Patient read fails the launch.
- The read is one deterministic collection Bundle (sorted, absolute fullUrls, resources as received) ingested as FHIR_BUNDLE under `epic-sandbox` (fhir.epic.com), `oracle-sandbox` (fhir-ehr-code.cerner.com) or `smart:<host:port>`; an unchanged chart is the same bytes, so no new rows. Absolute references equal to an entry fullUrl resolve at ingest.
- Launch-scoped reconcile: current = exactly the launch's source record, cutoff = run time; incoming = a seeded Synthea C-CDA the provider picks (suggested by same name + birth date). Runs store incoming_patient_id and current_source_record_id.
- Patient context: /demo and /reconcile list only seeded Synthea patients; a launched patient opens only with its own session (404 otherwise), and its decisions are attributed to `smart:<fhirUser>`.
- Write-back is a dry run: accepted NEW = create, accepted CHANGED or EDIT with a current row = update (same type only), SAME/CURRENT_ONLY/REJECT = nothing; "FHIR write" only if the launch's CapabilityStatement declares the interaction, else export package only. Never sent; the download is an EXPORT audit entry.
- Audit: LOGIN per completed launch, one READ per launch query (label and counts, no ids), READ of the outside patient on scoped runs.
- tests/mock-smart is test-only: auto-approving authorize, PKCE-checking token endpoint, EHR launcher, paged read-only FHIR over Synthea patients with `mock-<id>` ids. Its CapabilityStatement is a fixture, never cited as Epic's; `smart:capability` writes docs/reports/phase5-writeback-<source>.md only for the Epic and Oracle Health sandboxes.
- Oracle Health (Cerner) Millennium is a second SMART server on the same code path: same reads, scopes and write-back dry run; no vendor-specific branches until the sandbox run shows a need.
- Phase 6 identity is the SMART launch only. Roles VIEWER < PROVIDER < ADMIN; a user_roles grant keyed by actor `smart:<fhirUser>` wins, else Practitioner/PractitionerRole = PROVIDER and anyone else VIEWER. `pnpm roles` changes grants, audited as UPDATE/DELETE on UserRole.
- DEMO_MODE (1|true, 0|false; unset = on unless NODE_ENV=production) opens the seeded Synthea patients to `demo:provider` (PROVIDER, never ADMIN). Off: /demo and the /reconcile list are 404, the API needs a launched session.
- Roles are enforced on the server: route handlers answer 403, server actions redirect with the role message. Pages hide write controls from viewers.
- fhirUser comes only from a verified id_token: RS256/ES256 against the JWKS from OIDC discovery on the iss or token-endpoint origin, plus iss, aud, exp, iat. It is stored absolute (a relative one is resolved against the iss). Unverified = `smart:unknown-user`, VIEWER, not grantable.
- Encryption at rest: source_records.raw_text and transfer_jobs.bundle are `enc:<keyId>:<sealed>` (AES-256-GCM via the session sealer, AAD = column + row sha256). sha256 stays over the plaintext; plaintext still reads; a production build refuses to store without DATA_KEYS; `pnpm crypt:rotate` (and db:seed) re-seals.
- Canonical, reconcile and summary JSON stay readable to the app and rely on database-level encryption (SECURITY.md 14-15).
- audit_log hash chain: a BEFORE INSERT trigger, serialized by a transaction advisory lock, re-draws the id and sets hash = sha256 over prev_hash and the length-prefixed fields (time as ISO ms UTC, details as stored jsonb text). Existing rows were backfilled by the migration. Assumes READ COMMITTED.
- Audit writes stay last in their transactions, because the chain lock is held until commit.
- Audit export = NDJSON of the hashed fields as text plus a `{"chain": ...}` trailer. The chain is verified first; the export is an EXPORT row (entityType AuditLog). CLI or admin-only API.
- Rate limits: fixed windows in rate_limits, keyed by rule + session id, else sha256 of the X-Forwarded-For IP (only with TRUST_PROXY=1), else one shared bucket. 429 JSON + Retry-After; server actions redirect with a message; the callback counts per session.
- proxy.ts sets a nonce CSP ('strict-dynamic'; the root layout is dynamic so every page gets the nonce), frame-ancestors 'self' + SMART_<NAME>_FRAME_ANCESTORS (default: the iss origin), no X-Frame-Options, no-referrer, HSTS over HTTPS. COOP waits for the sandbox runs.
- Logs: src/log.ts writes an event plus allowlisted non-identifying fields; production console calls go through it (instrumentation.ts); route errors become 500 {error, requestId} (src/http.ts). Error pages (app/error-view.tsx) show the digest only.
- Accessibility gate: axe-core WCAG 2.1 A/AA in Playwright on every page, launched views and the error page included. Serious or critical issues and browser CSP violations fail the build.
- The vendored skills in .claude/skills (PR #1) are outside lint, typecheck and Prettier. When a skill conflicts with CLAUDE.md's protocol (subagents, stopping at gates), CLAUDE.md wins.
